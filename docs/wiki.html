Domaine métier

confirmedagents: onboarder · updated: 2026-07-07

L'outil sert à évaluer la maturité agile/produit d'une équipe à partir d'une grille de référence (~50 questions, 4 piliers), à en restituer une lecture agrégée (radar, dispersion) et à produire un support de restitution PowerPoint présenté en réunion d'équipe. Une vue de consolidation multi-équipes existe pour une lecture au niveau département. CONFIRMÉREADME.md:3-8

Personas

Répondant équipier Répondant manager Animateur / coach agile Sponsor / RH / direction
  1. Répondant – Équipier — fait un état des lieux honnête de son quotidien d'équipe ; craint que ses réponses individuelles remontent nommément à son manager.
  2. Répondant – Manager direct — répond au même questionnaire que l'équipe pour permettre le calcul d'un écart de perception ; risque de biais de désirabilité managériale.
  3. Animateur / Coach agile — administre la session, suit le taux de complétion, consulte les résultats agrégés, exporte la restitution.
  4. Sponsor / RH / Direction — vision consolidée multi-équipes par pilier ; granularité au moins équipe, jamais individuelle.

CONFIRMÉcadrage/personas.md:1-86

Parcours (experience map, 8 étapes)

  1. Invitation à la session — friction : manque de contexte sur l'objectif → faible taux de réponse.
  2. Identification du rôle (point critique) — nom/prénom nominatif, département, équipe, rôle, statut manager, "dans l'équipe au quotidien" (cette dernière paire porte le calcul de l'écart de perception, pas le statut manager seul).
  3. Remplissage du questionnaire (~50 questions, 4 piliers), navigation par pilier, sauvegarde/reprise par pilier complété.
  4. Soumission — verrouillage définitif jusqu'à réouverture par l'animateur.
  5. Agrégation et calcul des écarts — temps réel dès soumission, aucun seuil minimal d'anonymat (dès 1 réponse), écran nominatif pour l'animateur.
  6. Analyse et préparation de la restitution — pré-analyses (min/max/dispersion, taux de réponse), commentaire libre.
  7. Restitution à l'équipe — support PPT présenté par l'animateur.
  8. Consolidation multi-équipes — écran dédié sponsor/RH/direction, radar par département avec zoom équipe.

CONFIRMÉcadrage/experience-map.md:1-118

Difficultés identifiées

  • Parsing d'un fichier Excel à structure peu tabulaire (cellules fusionnées, symboles, texte concaténé).
  • Absence de seuil minimal d'anonymat — choix produit assumé, à signaler à l'écran si échantillon très faible.
  • Absence d'anonymat réel vis-à-vis de l'animateur — à communiquer explicitement dès l'invitation.
  • Saisie libre département/équipe → risque de doublons fragmentant la consolidation.

Décisions notables

référentiel

Ré-import non destructif par défaut : réconciliation par clé de contenu pour réutiliser le même question_id, entrée disparue archivée si elle porte des réponses. Mode remplacer = purge totale atomique. CONFIRMÉ

export

Export PPT en deux étapes : Puppeteer (Chrome headless) rasterise le radar SVG en PNG, puis un script Python (python-pptx) construit le .pptx. Un seul lancement de navigateur pour tous les radars d'un export. CONFIRMÉ

agrégation

Recalcul des agrégats à la demande (pas de table précalculée) — cohérent avec l'exigence de temps réel, mais réagrège l'ensemble des réponses à chaque requête. DÉDUIT

comparaison

La session précédente d'une équipe est retrouvée par égalité de chaîne sur equipe (pas un identifiant stable) — dépend de la cohérence apportée par la saisie tolérante. CONFIRMÉ

sécurité

Aucune authentification à ce stade (Epic 10 non implémenté) — aucun middleware d'authentification observé sur l'ensemble de server.js. CONFIRMÉ

environnements

3 environnements isolés en parallèle sur le même poste (DEV/PRE-PROD/PROD), port et base SQLite propres, chargés via node --env-file. CONFIRMÉ

Fragilités connues

  • Parsing Excel dépendant d'une structure implicite (motif de texte "PILIER - OBJECTIF", colonnes fixes 4/6/8/10 pour les niveaux) — pas de validation stricte au-delà du test "aucun pilier détecté". CONFIRMÉ
  • server.js en monolithe unique (929 lignes, ~25 routes) sans découpage en routeurs. CONFIRMÉ
  • Double implémentation du rendu radar (SVG serveur vs JS front dans resultats.html), sans test automatisé garantissant la parité. DÉDUIT
  • Aucune notion de client/organisation — référentiel/rôles/répondants globaux à l'installation. CONFIRMÉ
  • CHROME_PATH par défaut non portable (chemin Windows en dur). CONFIRMÉ

Conventions de code

mixedagents: onboarder · updated: 2026-07-08

Une configuration ESLint (flat config app/eslint.config.js, règles recommandées) est versionnée depuis le 2026-07-08 : globals Node/CommonJS pour src/+scripts/, navigateur pour src/public/. Lancée via npm run lint (dans app/) et en CI. Un .editorconfig racine fixe indentation, fins de ligne et encodage. Le formatage pur (Prettier) n'est volontairement pas verrouillé (reformatage global trop invasif). Les conventions ci-dessous restent en partie observées dans le code au-delà de ce que le linter impose. CONFIRMÉ2026-07-08 · app/eslint.config.js, .editorconfig, app/package.json

Nommage

  • Vocabulaire métier français préservé dans les identifiants : tables/colonnes SQL en snake_case français (sous_categories, ouverture_at, est_manager), fonctions/variables JS en camelCase français (getReferentiel, reconcileReferentiel, agregerResultats). CONFIRMÉ
  • Pas de classes : tous les modules src/*.js exportent des fonctions (module.exports = { ... }), style purement fonctionnel. CONFIRMÉ
  • Commentaires en français orientés "pourquoi" plutôt que "quoi", systématiquement au-dessus d'une fonction/bloc non trivial. CONFIRMÉ
  • Modules CommonJS ("type": "commonjs"), malgré un import() dynamique ponctuel pour dictionary-fr (ESM-only). CONFIRMÉ

Gestion d'erreurs et validation

  • Validation manuelle en tête de route, sans librairie de schéma (pas de zod/joi/ajv), messages d'erreur en français explicites (res.status(400).json({ error: '...' })). CONFIRMÉ
  • Transactions SQLite explicites (BEGIN/COMMIT/ROLLBACK) pour les opérations multi-tables sensibles. CONFIRMÉ
